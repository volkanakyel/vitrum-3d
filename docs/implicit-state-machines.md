# Implicit state machines in Vitrum

Original static audit of the working tree, 2026-11-08. Includes existing uncommitted changes in `LandingScene.vue` and `showcase.ts`.

## Fix status

All eight transition-gap groups below have been addressed. The inventory and original findings are retained as a **pre-fix snapshot**; their line numbers and descriptions of missing guards refer to that snapshot, not the current implementation.

| Original gap | Resolution | Regression coverage |
|---|---|---|
| 1. Import ownership | One cancellable owner covers sample rasterization, image decode, loader waits, trace/grid work, and linked-sample completion. Replacement, clear, and disposal invalidate continuations. | `tests/studio-state.test.ts`, `tests/async-state.test.ts`, `tests/studio-lifecycle.spec.ts` |
| 2. Shared busy flag | Separate trace/grid activity plus import ownership derive busy. Only current jobs settle their flags and errors. | `tests/studio-state.test.ts` |
| 3. Premature/inconsistent export | Export requires a current valid trace, matching geometry inputs, viewer availability, dimensions, and no processing/error. Parameters snap before export. GLB owns cloned geometry/maps; PNG restores viewport before encoding completes. | `tests/studio-state.test.ts`, `tests/export-state.test.ts`, `tests/studio-lifecycle.spec.ts` |
| 4. Stale results | Option changes invalidate revisions synchronously, before debounce. Worker source changes settle obsolete jobs; queued grids using an older trace are discarded. Grid edits during the final import hold trigger a fresh build. | `tests/studio-state.test.ts`, `tests/tracer-state.test.ts` |
| 5. User intent | Material, backdrop, and shape controls emit explicit edits. Automatic print and liquid restoration cannot overwrite those choices just because values happen to match defaults. | `tests/studio-state.test.ts` |
| 6. Hero cancellation | Worker termination rejects pending builds; sibling workers stop on failure. Cache waits, shader waits, and frame waits have settling cancellation. Warm-up barriers release in `finally`; component owns builds before dynamic import completes. | `tests/hero-marks.test.ts`, `tests/showcase-state.test.ts`, `tests/async-state.test.ts` |
| 7. Graphics availability | Both scene wrappers dispose/cancel on context loss and reconstruct from current inputs on restoration. Visibility cannot restart a lost instance. Studio exposes unavailable status and blocks export. Studio shader warm-up also releases its temporary geometry on disposal. | `tests/studio-lifecycle.spec.ts`, `tests/export-state.test.ts` |
| 8. Small lifecycle gaps | Panel waits/idle tasks, slider timers, and pointer-capture listeners clean up with component scope. Share serializes attempts, clears prior fallback, and ignores results after reset/unmount. | `tests/share-state.test.ts`, `tests/async-state.test.ts`; component cleanup inspected statically |

Additional regressions cover cancelled refreshes remaining unexportable and obsolete grid errors clearing when returning to a valid extrusion. Healthy small machines and library-owned behavior remain in their existing implementations; no state-machine dependency was added.

Verification uses real Vue scopes with controlled asynchronous boundaries, real Three.js geometry for export ownership, and Chromium/SwiftShader with actual workers and `WEBGL_lose_context`. Headless graphics tests do not cover physical GPU/driver behavior. Pointer cleanup was reviewed in code, not exercised by a dedicated gesture browser test.

Checks on 2026-11-08: `pnpm check` passed (typecheck; 65 tests across 14 files), `pnpm test:e2e` passed (3 Chromium tests), and `pnpm build` passed. Build emits a bundle-size warning and an unused-import warning from Nuxt's generated dependency code.

## Original inventory

**38 machine families**, with nested/parallel regions grouped by responsibility. This is an architectural grouping, not 38 independent finite-state machines. Numeric animation systems are hybrid machines: discrete lifecycle states plus continuous values.

Scope: first-party runtime code in `app/`, `server/`, and `nuxt.config.ts`; test inventory inspected. Generated output, dependencies, evaluation artifacts, and ordinary stateless geometry/raster calculations excluded. Library/browser-owned state is identified separately below. State names describe inferred behavior, not necessarily identifiers already present in code. Findings are source-based; race scenarios were not reproduced in a browser.

## Most consequential transition gaps

These are code-supported risks, not browser-reproduced bug reports.

1. **Imports have no owner or cancellation generation.** `useFile` can overlap through paste/drop/pick. Every invocation mutates the same `importing` object and clears it in `finally`. A slower import can replace a newer image; one completion can null another import's loader, after which its `.phase`/`.preview` write fails. `clearImage` and unmount do not invalidate outstanding decode/sleep continuations. The image-identity guards in trace/relief protect only those individual result writes, not the entire import. See #1, #2, #3.

2. **`busy` cannot represent concurrent work.** `runTrace` starts `void runRelief()` at line 323, which sets `busy = true`, then immediately assigns `busy = false` at line 327 while relief is still pending. Both runners also return early on discarded results before their trailing reset. Clearing a source during an outstanding job can therefore leave `busy` true without an owner. Error/completion from one job can overwrite another job's status. See #2, #3, #13.

3. **Export readiness is weaker than model readiness.** `ready` is only `!!trace` ([definition:121](/Users/volkanakyel/Developer/vitrum-3d/app/composables/useStudio.ts:121)); a zero-polygon result also qualifies. Export button uses only `!ready` ([page:117](/Users/volkanakyel/Developer/vitrum-3d/app/pages/studio.vue:117)). `doExport` guards only viewer existence and an existing export; Cmd/Ctrl+E reaches it before the keyboard handler's ready guard. Exports can therefore run during grid work or parameter easing. GLB reads material settings from `target` while cloning current mesh geometry; those can represent different revisions. See #4, #8, #16.

4. **Result freshness tracks image identity, not document revision.** A trace or relief response for the same image is accepted even after options or desired geometry change. Pending-job coalescing does not cancel an already running job. Relief captures crop/mask at enqueue time; processing a higher-priority trace first does not update that queued payload. Temporary older results are therefore allowed. Whether desirable preview behavior or a defect, it should be an explicit policy. See #2, #3, #13.

5. **Automatic versus user-selected print is ambiguous.** `autoFinish` clears only when finish category differs. After automatic print selection, picking another print preset leaves `autoFinish === 'print'`; next simple import can reset that deliberate selection to clear glass. Liquid restoration similarly infers user intent from equality; choosing a recognized liquid backdrop deliberately still makes it eligible for reset. See #5, #6, #7.

6. **Hero cancellation does not settle all waits.** `runWorker().terminate()` stops worker without resolving/rejecting `marks`. A load already awaiting those marks can remain pending after disposal. Hero warm-up also awaits a `compiled` release promise; returning after disposal before `release()` leaves that barrier unresolved. An import/constructor failure before build ownership transfers to `scene` can leave the locally started build outside component cleanup. See #28, #29.

7. **Context loss is not a durable availability state.** Landing context-loss handler clears ready/shown and sets scene visibility false, but does not mark load as cancelled or scene as lost. An in-progress load can later emit ready; a visibility change can re-enable rendering. No app-level context-restored transition is present. Studio wrapper has no explicit creation-error/context-loss branch. See #14, #28, #31.

8. **Some small machines lack cancellation/reset edges.** ControlPanel's delayed idle warming and two-frame callbacks are not cancelled on unmount. Slider pulse/spring/quiet/measurement timers have no scope cleanup. Share does not reset `fallbackUrl` at the start of a new attempt or on later success, and the landing page does not call `reset`; an old manual link can survive subsequent shares. These are smaller than import/job ownership but follow the same pattern. See #25, #27, #34.

## What to make explicit first

Start with **document/import ownership**, **trace/relief jobs**, and **exportable model revision**. One document generation should own its image, trace, grid, errors, and completion. Track jobs independently and derive busy state. Define whether export uses last complete revision or waits for requested revision.

Next: give hero preparation a settling cancellation path and durable unavailable state. Keep sheet position and gesture ownership as separate cooperating machines. Slider editing/dragging deserves a small tagged state; detent flashes and spring-back can remain parallel timers with cleanup.

No requirement to move everything into a state-machine library. Existing `presetToken` in Showcase already demonstrates a small, explicit ownership mechanism. Plain discriminated unions, transition functions, and revision IDs would address the most consequential gaps. Open/closed popovers, native details, pure derived mode visibility, and ordinary numeric settings do not warrant their own new controller.
